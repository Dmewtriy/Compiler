Лабораторная работа №1. Разработка пользовательского интерфейса (GUI) для языкового процессора

Цель работы

Создание кроссплатформенного графического интерфейса (GUI) для языкового процессора в виде специализированного текстового редактора.

Описание проекта

Приложение представляет собой текстовый редактор, который в дальнейшем будет расширен до полноценного языкового процессора для анализа исходного кода.

Основные возможности:

  • Работа с файлами (создание, открытие, сохранение с контролем изменений).
  • Полноценный блок редактирования текста (отмена действий, работа с буфером обмена).
  • Динамический интерфейс: редактор кода скрыт до момента создания или открытия файла.
  • Индикация несохраненных изменений через заголовок окна (символ *).
  • Предупреждения о потере данных при выходе или создании нового файла.

Используемые технологии

  • Язык программирования: C#
  • Платформа: .NET (Windows Forms)
  • Архитектурный паттерн: MVC
  • Среда разработки: Visual Studio 2026

  • Область редактирования: Поле RichTextBox, которое становится видимым только после инициализации файла.

  • Редактор поддерживает только текстовые форматы файлов (.txt, .cpp, .js и т.д.).

Постановка задачи

Диаграмма состояний


Краткое описание принципа его работы:

  1. Начало работы (Состояние 0) Автомат стартует из состояния 0. В зависимости от считанного символа (sc), он выбирает путь: Буква или подчеркивание : переход в состояние 1 для обработки слов. Пробел, скобки { } или точка с запятой ;: переход в соответствующие состояния (2, 3, 4, 5) для генерации кода конкретного символа. Любой другой символ: переход в состояние ERROR.

  2. Обработка идентификаторов и ключевых слов (Состояние 1) Цикл (петля): автомат остается в состоянии 1, пока считывает буквы (Б), цифры (Ц) или подчеркивания (_). Результат: по завершении цепочки автомат классифицирует слово: code 2: если это зарезервированное слово enum. code 3: если это зарезервированное слово case. code 1: для всех остальных пользовательских имен (идентификаторов id).

  3. Обработка одиночных символов (Состояния 2–5)

    • Состояние 2: пробел → code 4.

    • Состояние 3: фигурная скобка { → code 5.

    • Состояние 4: фигурная скобка } → code 6.

    • Состояние 5: точка с запятой ; → code 7.

  4. Завершение (OUT) После того как токен успешно распознан и его код сформирован, автомат возвращается в начало (OUT (start)) для чтения следующей порции данных.

Лабораторная работа 3. Разработка синтаксического анализатора (парсера)

Цель работы

Изучить назначение и принципы работы синтаксического анализатора в структуре компилятора. Спроектировать грамматику, построить соответствующую схему метода анализа грамматики и выполнить программную реализацию парсера с нейтрализацией синтаксических ошибок методом Айронса. Интегрировать разработанный модуль в ранее созданный графический интерфейс языкового процессора.

Постановка задачи

Разработать синтаксический анализатор для распознавания объявлений перечислений. Парсер должен принимать поток лексем, проверять их на соответствие грамматике и, в случае обнаружения ошибок, нейтрализовать их методом Айронса.

Разработка грамматики

		

			G[Z] = {Vt, Vn, Z, P}
Vt = {'enum', 'case', '{', '}', ';', 'space', 'a'...'z', 'A'...'Z', ‘0’…’9’}
Vn = {Z, ENUM, SPACE, ID, ENUM_BODY, CASE, SPACE_BTWN, CASE_ID, END_CASE, ENDBODY, END, Б, Ц}

		

			P = {
    Z -> 'enum' ENUM
    ENUM -> 'space' SPACE
    SPACE -> ('' | Б){Б | Ц | ‘_’} ID
    ID-> '{' ENUM_BODY
    ENUM_BODY -> 'case' CASE | '}' END_BODY
    CASE-> 'space' SPACE_BTWN
    SPACEBTWN-> ('' | Б){Б | Ц | ‘_’} CASE_ID
    CASE_ID-> ';' END_CASE
    END_CASE -> 'case' CASE | '}' END_BODY
    END_BODY -> ';' END
    Б → ‘a’ | ‘b’ | … | ‘z’ | ‘A’ | ‘B’ | … | ‘Z’
    Ц → ‘0’ | ‘1’ | … | ‘9’
}

Классификация грамматики

Согласно классификации Хомского, грамматика G[Z] является полностью автоматной.

Метод Айронса
Разрабатываемый синтаксический анализатор построен на базе автоматной грамматики. При нахождении лексемы, которая не соответствует грамматике предлагается свести алгоритм нейтрализации к последовательному удалению следующего символа во входной цепочке до тех пор, пока следующий символ не окажется одним из допустимых в данный момент разбора.
